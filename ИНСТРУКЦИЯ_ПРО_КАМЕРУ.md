# OmegaBot — ветка «Попытка в тех. зрение»

Эта ветка — попытка перенести проект на другую аппаратную платформу:
образовательный набор **ARP-DEK-STR-02** (плата, ~Arduino Mega-совместимая,
изготовитель ООО «Прикладная робототехника»), без манипулятора/схвата
из комплекта, но с добавлением модуля технического зрения **TrackingCam**.

Код и README из основной ветки (Raspberry Pi + отдельный Arduino +
USB-веб-камера) относятся к старой сборке робота и для этой платформы
**не подходят**. Здесь всё написано заново под новое железо.

---

## 1. Архитектура

```
┌──────────┐   Wi-Fi / TCP:5000    ┌──────────────┐   USB (mini-USB↔USB)   ┌───────────────────────┐
│    ПК    │ ◄────────────────────►│ Raspberry Pi │◄───────────────────────►│ Плата ARP-DEK-STR-02  │
│ (оператор│      управление       │   (сервер)   │   Serial (115200)       │ (моторы, ИК, УЗ,      │
│  + видео)│                       │              │                        │  энкодеры)            │
└──────────┘                       │              │                        └───────────┬───────────┘
     ▲                             │              │                                    │ UART
     │  USB (видео, отдельно)       │              │                                    ▼
     └─────────────────────────────┤              │                        ┌───────────────────────┐
                                    └──────────────┘                        │      TrackingCam       │
                                                                            └───────────────────────┘
```

Ключевое отличие от старой схемы: отдельного Arduino больше нет — моторы,
ИК-датчики, УЗ-дальномеры и энкодеры висят прямо на плате ARP-DEK-STR-02,
и она же по USB (Serial, как обычная Arduino-плата) общается с Raspberry Pi.
TrackingCam подключена к этой же плате по UART для распознавания объектов,
и, отдельно, может быть подключена по USB напрямую к Raspberry Pi для
видео — подробности в разделе 5.

**Роли файлов:**

| Файл | Где запускается | Что делает |
|---|---|---|
| `str02/str02_controller.ino` | Плата ARP-DEK-STR-02 | Моторы, ИК, УЗ, энкодеры, чтение TrackingCam, приём команд/отправка телеметрии по Serial |
| `labirinth_server.cpp` (требует обновления под новый протокол) | Raspberry Pi | TCP-сервер для ПК ↔ Serial-мост к плате робота |
| `labirinth_client.cpp` / `labirinth_server_with_joystick.cpp` | ПК (Windows) | Управление с клавиатуры/джойстика |
| `video_server.cpp` / `video_client.cpp` (требуют проверки на новом железе) | Raspberry Pi / ПК | Видеопоток оператору, см. раздел 5 |

> На момент этого коммита серверный код на Raspberry Pi (`labirinth_server.cpp`)
> ещё не обновлён под новую плату — это следующий шаг.

---

## 2. Что нужно из железа

* Плата ARP-DEK-STR-02, собранная на шасси (без схвата).
* Raspberry Pi (любая модель с USB и Wi-Fi).
* Модуль **TrackingCam**, подключённый к плате по UART (4 провода:
  +5В, GND, TX-камеры→RX-платы, RX-платы→TX-камеры — единственный
  разъём под это на плате, номер аппаратного UART внутри платы
  подбирается опытным путём, см. комментарий в `str02_controller.ino`).
* Кабель mini-USB↔USB для связи платы с Raspberry Pi.
* Отдельный кабель USB для TrackingCam → Raspberry Pi, если нужно видео
  оператору (см. раздел 5) — TrackingCam поддерживает одновременное
  подключение по UART (к плате) и по USB (к ПК/Pi), но **нельзя питать
  модуль одновременно с обеих сторон** — питание должно идти только
  с одной стороны (либо от платы через UART-разъём, либо по USB).

---

## 3. Прошивка платы робота

1. Установить библиотеку `TrackingCamDxlUart` (Файл → Настройки →
   добавить .zip библиотеку — она отдельно скачивается с сайта
   производителя, в репозитории не лежит из-за размера/лицензии).
2. Открыть `str02/str02_controller.ino` в Arduino IDE.
3. Выбрать плату (Mega-совместимая) и порт.
4. Загрузить скетч.
5. Перед тем как полагаться на прошивку — **проверить распиновку ИК-датчиков
   на реальной плате**: если центральный/левый ИК висят на D0/D1, это те же
   линии, что и Serial-связь с Raspberry Pi (на ATmega2560, в отличие от
   Leonardo-подобных плат, USB и UART0 — это физически одно и то же). Если
   конфликт подтвердится, эти датчики нужно перенести на другие пины и
   поправить класс `Pins` в скетче.

---

## 4. Запуск всей системы

1. Прошить плату робота (раздел 3), собрать провода по разделу 2.
2. Подключить плату к Raspberry Pi по USB.
3. На Raspberry Pi собрать и запустить серверный код (после того как он
   будет обновлён под новый протокол — см. TODO выше).
4. На ПК запустить клиент (`labirinth_client.exe` или
   `labirinth_server_with_joystick.exe`) — управление тем же протоколом
   `F/B/L/R/S`, что использовался раньше.
5. Если видео нужно — отдельно поднять видеоканал, см. раздел 5.

---

## 5. Видео для оператора: как это теперь работает

Это отдельный и не совсем очевидный момент, разберём подробно.

**TrackingCam физически может выдавать два разных вида данных, по
двум разным проводным путям одновременно:**

1. **По UART → плата робота.** Это протокол Dynamixel, обёрнутый
   библиотекой `TrackingCamDxlUart`. По этому каналу модуль не
   передаёт видео — только уже посчитанные координаты распознанных
   цветных объектов/областей (`.obj[i].cx/cy/...`). Именно это
   используется в `str02_controller.ino` для автономного распознавания
   меток.
2. **По USB → компьютер.** Судя по паспортным характеристикам модуля
   (производитель заявляет поддержку видеопотока 640×480@30fps по USB),
   TrackingCam при прямом подключении к ПК может отдавать именно
   картинку, а не координаты — этим пользуется их фирменное приложение
   TrackingCam App при настройке (окно Image с живым видео).

Так как оба канала независимы и, судя по документации, могут работать
одновременно (с оговоркой про питание только с одной стороны), логичный
план — воткнуть TrackingCam ещё и по USB в Raspberry Pi, отдельно от
UART-провода к плате робота, и раздавать это видео оператору так же,
как раньше раздавался поток с обычной веб-камеры (`video_server.cpp` /
`video_client.cpp`, JPEG-кадры по TCP).

**Что пока не подтверждено и нужно проверить руками:** неизвестно, определится
ли TrackingCam на Raspberry Pi как стандартная UVC-камера (тогда
`video_server.cpp` в связке с OpenCV `VideoCapture` заработает вообще
без переделок — просто другой `CAMERA_INDEX`), или для получения видео
на Linux обязательно нужно их фирменное приложение TrackingCam App
(судя по документации, оно как минимум для Windows). Проверяется так:
подключить TrackingCam по USB к Raspberry Pi и посмотреть

```bash
lsusb
v4l2-ctl --list-devices
```

Если появляется `/dev/videoX` — это обычная UVC-камера, и старый
видео-пайплайн из ветки `main` можно почти без изменений перенести
сюда. Если нет — придётся либо ставить отдельную обычную USB-камеру
только для видео оператору (а TrackingCam оставить исключительно на
UART для распознавания), либо разбираться с их протоколом отдельно.
