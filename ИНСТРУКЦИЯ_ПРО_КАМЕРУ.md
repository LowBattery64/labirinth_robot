# OmegaBot — ветка «hotfix+webcam usage»

Эта ветка переносит проект на другую аппаратную платформу:
образовательный набор **ARP-DEK-STR-02** (плата, ~Arduino Mega-совместимая,
изготовитель ООО «Прикладная робототехника»), без манипулятора/схвата
из комплекта. Изначально пробовали добавить модуль технического зрения
**TrackingCam** — от этой идеи отказались (см. раздел 5), сейчас видео
для оператора идёт через обычную **USB-веб-камеру**, тем же способом,
что и в самой первой версии проекта.

README и код из ветки `main` (Raspberry Pi + отдельный Arduino) относятся
к старой сборке робота и для этой платформы не подходят.

---

## 1. Архитектура

```
┌──────────┐   Wi-Fi / TCP:5000     ┌──────────────┐   USB (mini-USB↔USB)   ┌───────────────────────┐
│    ПК    │ ◄─────────────────────►│ Raspberry Pi │◄────────────────────────► Плата ARP-DEK-STR-02  │
│ (оператор)│      управление        │   (сервер)   │   Serial (115200)       │ (моторы, ИК, УЗ,       │
└──────────┘                        │              │                        │  энкодеры)             │
     ▲                              │              │                        └───────────────────────┘
     │   TCP:5001, видео             │              │
     │                              │              │
     └──────────────────────────────┤              │◄──── USB ──── USB-веб-камера
                                     └──────────────┘
```

Управление (порт 5000) и видео (порт 5001) — два независимых канала и два
независимых процесса на Raspberry Pi, как и в самой первой версии проекта.
Плата робота к видео никакого отношения не имеет — камера подключена
напрямую к Raspberry Pi обычным USB и полностью независима от Serial-связи
с платой.

**Роли файлов:**

| Файл | Где запускается | Что делает |
|---|---|---|
| `str02-controller.ino` | Плата ARP-DEK-STR-02 | Моторы, ИК-датчик, УЗ, энкодеры, приём команд/отправка телеметрии по Serial |
| `labirinth_server.cpp` | Raspberry Pi | TCP-сервер для ПК ↔ Serial-мост к плате робота, ретрансляция телеметрии |
| `labirinth_client.cpp` / `labirinth_server_with_joystick.cpp` | ПК (Windows) | Управление с клавиатуры/джойстика |
| `video_server.cpp` | Raspberry Pi | Захватывает кадры с USB-веб-камеры, шлёт JPEG по TCP (порт 5001) |
| `video_client.cpp` | ПК (Windows) | Принимает JPEG-кадры и показывает окно с видео |
| `ИНСТРУКЦИЯ_ПРО_КАМЕРУ.md` | — | Устарела, оставлена как история попытки с TrackingCam (см. раздел 5) |

---

## 2. Что нужно из железа

* Плата ARP-DEK-STR-02, собранная на шасси (без схвата).
* Raspberry Pi (любая модель с USB и Wi-Fi).
* Обычная USB-веб-камера, подключённая к Raspberry Pi.
* Кабель mini-USB↔USB для связи платы с Raspberry Pi.
* **Только один ИК-датчик препятствий** — на D2. Датчики, которые раньше
  стояли на D0/D1, отключены и физически сняты (см. раздел 4) — это не
  временная мера, а следствие подтверждённого конфликта пинов.

---

## 3. Прошивка платы робота

1. Открыть `str02-controller.ino` в Arduino IDE.
2. Выбрать плату (Mega-совместимая) и порт.
3. Загрузить скетч. Библиотека TrackingCam для этого больше не нужна —
   скетч её не использует.

---

## 4. Важно: конфликт пинов D0/D1

Подтверждено на практике: на плате ARP-DEK-STR-02 пины D0/D1 физически
являются тем же аппаратным UART0, через который плата по USB общается с
Raspberry Pi. Два ИК-датчика, которые изначально висели на этих пинах
(центральный и левый), конфликтовали со связью с Pi — их пришлось
отключить и снять. Сейчас в проекте остался только один ИК-датчик,
на D2 (`IRSensorArray::frontBlocked()` в `str02-controller.ino`).

Если по факту у вас сохранился ещё один ИК-датчик и он переставлен на
другой свободный пин — допишите его в классы `Pins` и `IRSensorArray`
в `str02-controller.ino`, и добавьте значение в `sendTelemetry()`.

---

## 5. Видео для оператора: почему не TrackingCam

Изначально в этой ветке пробовали получать видео через модуль
TrackingCam. По документации производителя TrackingCam действительно
поддерживает как передачу распознанных объектов по UART/Dynamixel (для
платы робота), так и отдельный видеопоток по USB на ПК — теоретически
оба канала можно было использовать одновременно.

Решили не продолжать с этим модулем в данной сборке и вернуться к
обычной USB-веб-камере — тому же решению, что использовалось в самой
первой версии проекта. Подробности прежней попытки с TrackingCam
(распиновка UART, работа с библиотекой `TrackingCamDxlUart`) оставлены
в `ИНСТРУКЦИЯ_ПРО_КАМЕРУ.md` как история, но в текущей сборке не
используются.

Видео теперь работает так: `video_server.cpp` на Raspberry Pi берёт
кадры с обычной USB-камеры через OpenCV (`cv::VideoCapture`), кодирует
в JPEG и шлёт по TCP на порт 5001. `video_client.cpp` на ПК принимает
кадры и показывает окно с видео. Это полностью независимо от платы
робота и от Serial-связи с ней.

### 5.1. Установка OpenCV на Raspberry Pi

```bash
sudo apt update
sudo apt install -y libopencv-dev pkg-config
```

### 5.2. Сборка видео-сервера на Raspberry Pi

```bash
g++ -std=c++17 -Wall -Wextra -o video_server video_server.cpp \
    $(pkg-config --cflags --libs opencv4)
```

Если `pkg-config` не находит `opencv4`:

```bash
g++ -std=c++17 -Wall -Wextra -I/usr/include/opencv4 -o video_server \
    video_server.cpp -lopencv_core -lopencv_imgcodecs -lopencv_videoio
```

### 5.3. Установка OpenCV и сборка видео-клиента на ПК (Windows)

Через [vcpkg](https://github.com/microsoft/vcpkg):

```powershell
git clone https://github.com/microsoft/vcpkg
cd vcpkg
.\bootstrap-vcpkg.bat
.\vcpkg install opencv:x64-windows
```

```powershell
g++ -std=c++17 -Wall -Wextra -o video_client.exe video_client.cpp -lws2_32 ^
    -I <путь_к_vcpkg>\installed\x64-windows\include ^
    -L <путь_к_vcpkg>\installed\x64-windows\lib ^
    -lopencv_core4 -lopencv_imgcodecs4 -lopencv_highgui4
```

(точные имена `-lopencv_coreXXX` зависят от версии OpenCV — смотрите
в `<vcpkg>\installed\x64-windows\lib`.)

### 5.4. Запуск видео

На Raspberry Pi:

```bash
./video_server
```

На ПК:

```cmd
video_client.exe IP_ПЛАТЫ
```

Откроется окно с видео. `Q` или `Esc` — закрыть.

## 6. Запуск всей системы

1. Прошить плату робота (раздел 3), проверить распиновку ИК-датчика (раздел 4).
2. Подключить плату к Raspberry Pi по USB; подключить веб-камеру к Raspberry Pi отдельным USB-портом.
3. На Raspberry Pi собрать и запустить сервер управления:
   `g++ -std=c++17 -o labirinth_server labirinth_server.cpp && ./labirinth_server`
4. На Raspberry Pi (в отдельном окне/сессии) собрать и запустить видео-сервер (раздел 5.2, 5.4).
5. На ПК запустить клиент управления (`labirinth_client.exe` или `labirinth_server_with_joystick.exe`) и, отдельно, `video_client.exe`.

# OmegaBot — ветка «Попытка в тех. зрение»

Эта ветка — попытка перенести проект на другую аппаратную платформу:
образовательный набор **ARP-DEK-STR-02** (плата, ~Arduino Mega-совместимая,
изготовитель ООО «Прикладная робототехника»), без манипулятора/схвата
из комплекта, но с добавлением модуля технического зрения **TrackingCam**.

Код и README из основной ветки (Raspberry Pi + отдельный Arduino +
USB-веб-камера) относятся к старой сборке робота и для этой платформы
**не подходят**. Здесь всё написано заново под новое железо.

---

## 1. Архитектура

```
┌──────────┐   Wi-Fi / TCP:5000    ┌──────────────┐   USB (mini-USB↔USB)   ┌───────────────────────┐
│    ПК    │ ◄────────────────────►│ Raspberry Pi │◄───────────────────────►│ Плата ARP-DEK-STR-02  │
│ (оператор│      управление       │   (сервер)   │   Serial (115200)       │ (моторы, ИК, УЗ,      │
│  + видео)│                       │              │                        │  энкодеры)            │
└──────────┘                       │              │                        └───────────┬───────────┘
     ▲                             │              │                                    │ UART
     │  USB (видео, отдельно)       │              │                                    ▼
     └─────────────────────────────┤              │                        ┌───────────────────────┐
                                    └──────────────┘                        │      TrackingCam       │
                                                                            └───────────────────────┘
```

Ключевое отличие от старой схемы: отдельного Arduino больше нет — моторы,
ИК-датчики, УЗ-дальномеры и энкодеры висят прямо на плате ARP-DEK-STR-02,
и она же по USB (Serial, как обычная Arduino-плата) общается с Raspberry Pi.
TrackingCam подключена к этой же плате по UART для распознавания объектов,
и, отдельно, может быть подключена по USB напрямую к Raspberry Pi для
видео — подробности в разделе 5.

**Роли файлов:**

| Файл | Где запускается | Что делает |
|---|---|---|
| `str02/str02_controller.ino` | Плата ARP-DEK-STR-02 | Моторы, ИК, УЗ, энкодеры, чтение TrackingCam, приём команд/отправка телеметрии по Serial |
| `labirinth_server.cpp` | Raspberry Pi | TCP-сервер для ПК ↔ Serial-мост к плате робота, плюс ретрансляция телеметрии платы оператору |
| `labirinth_client.cpp` / `labirinth_server_with_joystick.cpp` | ПК (Windows) | Управление с клавиатуры/джойстика |
| `video_server.cpp` / `video_client.cpp` (требуют проверки на новом железе) | Raspberry Pi / ПК | Видеопоток оператору, см. раздел 5 |

> Серверный код на Raspberry Pi (`labirinth_server.cpp`) уже обновлён под
> новую плату и умеет одновременно принимать команды от ПК и пересылать
> ему телеметрию платы. Видео (раздел 5) в этот сервер пока не встроено —
> это отдельный процесс/канал.

---

## 2. Что нужно из железа

* Плата ARP-DEK-STR-02, собранная на шасси (без схвата).
* Raspberry Pi (любая модель с USB и Wi-Fi).
* Модуль **TrackingCam**, подключённый к плате по UART (4 провода:
  +5В, GND, TX-камеры→RX-платы, RX-платы→TX-камеры — единственный
  разъём под это на плате, номер аппаратного UART внутри платы
  подбирается опытным путём, см. комментарий в `str02_controller.ino`).
* Кабель mini-USB↔USB для связи платы с Raspberry Pi.
* Отдельный кабель USB для TrackingCam → Raspberry Pi, если нужно видео
  оператору (см. раздел 5) — TrackingCam поддерживает одновременное
  подключение по UART (к плате) и по USB (к ПК/Pi), но **нельзя питать
  модуль одновременно с обеих сторон** — питание должно идти только
  с одной стороны (либо от платы через UART-разъём, либо по USB).

---

## 3. Прошивка платы робота

1. Установить библиотеку `TrackingCamDxlUart` (Файл → Настройки →
   добавить .zip библиотеку — она отдельно скачивается с сайта
   производителя, в репозитории не лежит из-за размера/лицензии).
2. Открыть `str02/str02_controller.ino` в Arduino IDE.
3. Выбрать плату (Mega-совместимая) и порт.
4. Загрузить скетч.
5. Перед тем как полагаться на прошивку — **проверить распиновку ИК-датчиков
   на реальной плате**: если центральный/левый ИК висят на D0/D1, это те же
   линии, что и Serial-связь с Raspberry Pi (на ATmega2560, в отличие от
   Leonardo-подобных плат, USB и UART0 — это физически одно и то же). Если
   конфликт подтвердится, эти датчики нужно перенести на другие пины и
   поправить класс `Pins` в скетче.

## 4. Запуск всей системы

1. Прошить плату робота (раздел 3), собрать провода по разделу 2.
2. Подключить плату к Raspberry Pi по USB.
3. На Raspberry Pi собрать и запустить `labirinth_server.cpp`:
   `g++ -std=c++17 -o labirinth_server labirinth_server.cpp && ./labirinth_server`
4. На ПК запустить клиент (`labirinth_client.exe` или
   `labirinth_server_with_joystick.exe`) — управление тем же протоколом
   `F/B/L/R/S`, что использовался раньше.
5. Если видео нужно — отдельно поднять видеоканал, см. раздел 5.

## 5. Видео для оператора: как это теперь работает

Это отдельный и не совсем очевидный момент, разберём подробно.

**TrackingCam физически может выдавать два разных вида данных, по
двум разным проводным путям одновременно:**

1. **По UART → плата робота.** Это протокол Dynamixel, обёрнутый
   библиотекой `TrackingCamDxlUart`. По этому каналу модуль не
   передаёт видео — только уже посчитанные координаты распознанных
   цветных объектов/областей (`.obj[i].cx/cy/...`). Именно это
   используется в `str02_controller.ino` для автономного распознавания
   меток.
2. **По USB → компьютер.** Судя по паспортным характеристикам модуля
   (производитель заявляет поддержку видеопотока 640×480@30fps по USB),
   TrackingCam при прямом подключении к ПК может отдавать именно
   картинку, а не координаты — этим пользуется их фирменное приложение
   TrackingCam App при настройке (окно Image с живым видео).

Так как оба канала независимы и, судя по документации, могут работать
одновременно (с оговоркой про питание только с одной стороны), логичный
план — воткнуть TrackingCam ещё и по USB в Raspberry Pi, отдельно от
UART-провода к плате робота, и раздавать это видео оператору так же,
как раньше раздавался поток с обычной веб-камеры (`video_server.cpp` /
`video_client.cpp`, JPEG-кадры по TCP).

**Что пока не подтверждено и нужно проверить руками:** неизвестно, определится
ли TrackingCam на Raspberry Pi как стандартная UVC-камера (тогда
`video_server.cpp` в связке с OpenCV `VideoCapture` заработает вообще
без переделок — просто другой `CAMERA_INDEX`), или для получения видео
на Linux обязательно нужно их фирменное приложение TrackingCam App
(судя по документации, оно как минимум для Windows). Проверяется так:
подключить TrackingCam по USB к Raspberry Pi и посмотреть

```bash
lsusb
v4l2-ctl --list-devices
```

Если появляется `/dev/videoX` — это обычная UVC-камера, и старый
видео-пайплайн из ветки `main` можно почти без изменений перенести
сюда. Если нет — придётся либо ставить отдельную обычную USB-камеру
только для видео оператору (а TrackingCam оставить исключительно на
UART для распознавания), либо разбираться с их протоколом отдельно.
