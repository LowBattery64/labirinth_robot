# OmegaBot Operator Console

Графическое приложение оператора на Qt 6 для телеуправления роботом.

Папка содержит только код самого операторского приложения. Raspberry Pi, Arduino и камера находятся за пределами этой папки и рассматриваются здесь только в той части, которая необходима для обмена данными с интерфейсом.

## Состав

### CMakeLists.txt

Файл сборки проекта.

Задаёт:

- C++17;
- автоматический запуск Qt MOC;
- зависимости Qt 6: `Widgets` и `Network`;
- список исходных файлов;
- исполняемый файл `OmegaBotOperator`.

При добавлении нового `.cpp` или `.h` файла его нужно добавить в `add_executable()`.

---

### main.cpp

Точка входа приложения.

Создаёт `QApplication`, главное окно `MainWindow` и запускает цикл Qt.

Обычно изменять этот файл не требуется.

---

### MainWindow.h

Объявление главного окна.

Содержит:

- элементы интерфейса;
- объекты `RobotConnection` и `VideoConnection`;
- обработчики клавиатуры;
- функции построения интерфейса;
- обработчики телеметрии и постоянного журнала.

---

### MainWindow.cpp

Основной файл интерфейса.

Здесь находятся:

- создание всех элементов окна;
- расположение кнопок и информационных блоков;
- обработка команд управления;
- обработка клавиатуры;
- отображение телеметрии;
- отображение видеокадров;
- выбор качества видеопотока;
- управление записью видео;
- журнал оператора;
- стили интерфейса;
- адрес Raspberry Pi.

Это основной файл, который нужно изучать при изменении внешнего вида и поведения интерфейса.

---

### RobotConnection.h / RobotConnection.cpp

Класс сетевого соединения с роботом.

Использует TCP через Qt `QTcpSocket`.

Функции класса:

- подключение к Raspberry Pi;
- отправка команд;
- получение телеметрии;
- получение событий сервера;
- отслеживание состояния соединения;
- обработка сетевых ошибок.

Текущая команда отправляется повторно каждые 100 мс.

Команды:

| Команда | Значение |
|---|---|
| `F` | вперёд |
| `B` | назад |
| `L` | влево |
| `R` | вправо |
| `S` | стоп |

Команда передаётся одной буквой с переводом строки.

---

### VideoConnection.h / VideoConnection.cpp

Класс получения видеопотока.

Подключается к TCP-соединению и получает последовательность JPEG-кадров.

Формат одного кадра:

```text
[4 байта: размер JPEG в big-endian]
[JPEG данные]
```

Максимально допустимый размер одного кадра в клиенте — 10 МБ.

После получения кадра:

1. данные извлекаются из TCP-буфера;
2. JPEG декодируется в `QImage`;
3. кадр передаётся в `MainWindow`;
4. обновляется статистика FPS и размера JPEG.

---

### OperatorLogger.h / OperatorLogger.cpp

Класс постоянного журналирования на ПК оператора.

Файлы:

    %LOCALAPPDATA%/OmegaBotOperator/logs/operator.log
    %LOCALAPPDATA%/OmegaBotOperator/logs/telemetry.csv

Путь формируется через QStandardPaths::AppLocalDataLocation.

operator.log открывается в режиме добавления и не очищается при запуске. В интерфейсе при старте загружаются последние 200 строк этого файла.

Для событий сохраняются локальное время ПК и, если событие пришло от Raspberry Pi, исходное серверное время.

telemetry.csv записывает каждый принятый образец телеметрии отдельно от текстового журнала. В строке сохраняются оба времени, разобранные поля телеметрии и исходная строка.

---

### Telemetry.h

Содержит структуру `Telemetry` и функцию разбора телеметрии.

Интерфейс принимает строку вида:

```text
T,2026-09-27 21:06:25.123,IR,0,US,120,85,90,ENC,123,119,SAFE,0,CMD,F,WD,0
```

Второе поле — временная отметка Raspberry Pi. Для совместимости старый формат без этой отметки также разбирается.

Из неё используются:

- состояние ИК-блокировки;
- расстояния ультразвуковых датчиков;
- состояние защиты;
- текущая команда;
- состояние watchdog.

Формат самой телеметрии формируется кодом за пределами `operator_ui`.

# Требования

## Операционная система

Текущая инструкция рассчитана на Windows x64.

## Компилятор

Используется MSVC 2022.

## Qt

Требуется Qt 6 с компонентами:

- Qt6::Widgets
- Qt6::Network

Для Qt 6 на Windows необходимо использовать сборку Qt под тот же компилятор, которым собирается приложение. Для текущей конфигурации используется MSVC 2022 x64.

## CMake

Минимальная версия, указанная в `CMakeLists.txt`:

```text
3.16
```

---

# Сборка на другом ПК

## 1. Установить инструменты

Необходимы:

- Visual Studio 2022 с компонентами C++;
- Qt 6 для MSVC 2022 x64;
- CMake.

Проверить CMake:

```powershell
cmake --version
```

## 2. Проверить расположение Qt

Например:

```text
C:\Qt\6.8.3\msvc2022_64
```

Точная версия Qt может отличаться.

## 3. Создать конфигурацию

Из корня репозитория:

```powershell
cmake -S operator_ui -B operator_ui/build -G "Visual Studio 17 2022" -A x64
```

Если CMake не находит Qt, указать путь вручную:

```powershell
cmake -S operator_ui -B operator_ui/build -G "Visual Studio 17 2022" -A x64 -DCMAKE_PREFIX_PATH="C:\Qt\6.8.3\msvc2022_64"
```

Путь нужно заменить на фактическое расположение Qt.

## 4. Собрать Release

```powershell
cmake --build operator_ui/build --config Release
```

Исполняемый файл:

```text
operator_ui/build/Release/OmegaBotOperator.exe
```

# Запуск

Приложение автоматически пытается подключиться к Raspberry Pi при создании `MainWindow`.

Текущий адрес задаётся в конструкторе `MainWindow`:

```cpp
robot.connectToRobot("10.109.150.232");
video.connectToCameraBridge("10.109.150.232");
```

Используются три TCP-соединения:

| Назначение | Адрес | Порт |
|---|---|---:|
| Управление и телеметрия | Raspberry Pi | 5000 |
| Видео | Raspberry Pi | 5001 |
| Управление видео | Raspberry Pi | 5002 |

Серверы на Raspberry Pi не входят в эту папку. Интерфейс только подключается к ним.

---

# Управление

Клавиатура обрабатывается в `MainWindow::keyPressEvent()`.

Текущее соответствие:

| Клавиша | Команда |
|---|---|
| W / ↑ | `F` — вперёд |
| S / ↓ | `B` — назад |
| A / ← | `L` — влево |
| D / → | `R` — вправо |
| Space | `S` — стоп |

Отпускание клавиши команду не меняет.

Это важно: текущая реализация использует модель «после нажатия команда сохраняется», а не «движение только пока клавиша зажата».

Кнопка `STOP` и кнопка `АВАРИЙНАЯ ОСТАНОВКА` также отправляют `S`.

---

# Название и оформление интерфейса

Название окна и центральный заголовок задаются в `MainWindow.cpp`.

Текущая схема оформления:

- слева — неоновая надпись `Drive`;
- по центру — неоновое название `ГОСЛИНГМОБИЛЬ`;
- справа — состояния робота и видео.

Название окна:

```cpp
setWindowTitle("Гослингмобиль — Operator Console");
```

Центральный заголовок:

```cpp
auto* title = new QLabel("ГОСЛИНГМОБИЛЬ");
```

Неоновая надпись `Drive` создаётся отдельным `QLabel` и оформляется через `QGraphicsDropShadowEffect`.

Поиск по проекту удобно выполнять по слову:

```text
OmegaBot
```

# Управление качеством видео и записью

Под видеополем находятся два элемента управления:

- **КАЧЕСТВО** — `ВЫСОКОЕ`, `СРЕДНЕЕ`, `НИЗКОЕ`;
- кнопка **НАЧАТЬ ЗАПИСЬ / ОСТАНОВИТЬ ЗАПИСЬ**.

Профили применяются на Raspberry Pi перед отправкой кадра оператору:

| Профиль | Масштаб | JPEG quality |
|---|---:|---:|
| ВЫСОКОЕ | 100% | исходный кадр |
| СРЕДНЕЕ | 75% | 70 |
| НИЗКОЕ | 50% | 55 |

Таким образом, переключение качества реально уменьшает размер передаваемого JPEG и нагрузку на канал. Камера при этом продолжает работать в исходном режиме.

Управление выполняется отдельным TCP-каналом Raspberry Pi:

```text
5002 — команды качества и записи
```

Команды протокола:

```text
QUALITY HIGH
QUALITY MEDIUM
QUALITY LOW
RECORD START
RECORD STOP
STATUS
```

Запись по умолчанию не запускается автоматически. Каталог записи передаётся `camera_bridge.py` из `scripts/start_robot.sh`, а фактический старт и остановка выполняются кнопкой оператора.

# Как изменить внешний вид

Весь интерфейс создаётся программно в:

```text
MainWindow.cpp
```

Qt Designer и `.ui` файлы не используются.

## Изменение размеров окна

В `setupUi()`:

```cpp
resize(1280, 800);
setMinimumSize(1000, 650);
```

## Изменение размера видеополя

Там же:

```cpp
videoLabel->setMinimumSize(700, 480);
```

## Изменение подписей кнопок

Кнопки создаются через:

```cpp
controlButton("▲\\nW / ↑", 'F');
controlButton("◀\\nA / ←", 'L');
controlButton("■\\nSTOP", 'S');
controlButton("▶\\nD / →", 'R');
controlButton("▼\\nS / ↓", 'B');
```

Текст можно изменить, не меняя саму команду.

Например:

```cpp
controlButton("ВПЕРЁД", 'F');
```

## Изменение цветов и шрифтов

В конце `setupUi()` находится общий Qt Style Sheet:

```cpp
setStyleSheet(R"(
    ...
)");
```

Здесь задаются:

- фон;
- цвет текста;
- размеры шрифтов;
- внешний вид кнопок;
- цвета статусов;
- оформление панели;
- оформление видеополя.

Для изменения внешнего вида в первую очередь следует искать нужный селектор в этом блоке.

# Как изменить IP или порт

IP Raspberry Pi задаётся в `MainWindow.cpp`:

```cpp
robot.connectToRobot("10.109.150.232");
video.connectToCameraBridge("10.109.150.232");
```

Если адрес Raspberry Pi изменился, изменить обе строки.

Порты по умолчанию заданы в классах:

```cpp
RobotConnection::connectToRobot(address, port = 5000);
VideoConnection::connectToCameraBridge(address, port = 5001);
```

Их можно изменить непосредственно при вызове:

```cpp
robot.connectToRobot("10.109.150.232", 5000);
video.connectToCameraBridge("10.109.150.232", 5001);
```

# Как добавить новую кнопку

Основная логика находится в `MainWindow::setupUi()`.

Простейший вариант:

1. создать `QPushButton`;
2. добавить его в нужный layout;
3. подключить сигнал `clicked`;
4. вызвать нужную функцию.

Для команды роботу удобно использовать существующий механизм:

```cpp
connect(button, &QPushButton::clicked, this, [this] {
    setCommand('F');
});
```

Если команда должна быть новой, например `X`, сначала нужно убедиться, что код на Raspberry Pi и Arduino тоже понимает эту команду. Само добавление кнопки в Qt не добавляет новую возможность роботу.

---

# Как добавить новую клавишу

Клавиши обрабатываются в:

```cpp
MainWindow::keyPressEvent()
```

Например:

```cpp
case Qt::Key_E:
    setCommand('X');
    break;
```

После этого команда `X` будет отправляться при нажатии E.

Если команда новая, её обработка также должна существовать в коде робота за пределами этой папки.

---

# Как добавить новый элемент телеметрии

Структура данных находится в:

```text
Telemetry.h
```

Сначала добавить новое поле в `Telemetry`.

Затем добавить его разбор в `parseTelemetry()`.

После этого вывести значение в `MainWindow::updateTelemetry()`.

Общая схема:

```text
Raspberry Pi
    |
    | строка телеметрии
    v
RobotConnection
    |
    v
parseTelemetry()
    |
    v
Telemetry
    |
    v
MainWindow::updateTelemetry()
    |
    v
элемент интерфейса
```

Формат строки должен соответствовать тому, что отправляет сервер. Изменение только `Telemetry.h` не заставит Raspberry Pi начать передавать новое значение.

# Как добавить новый функционал

Перед добавлением функции сначала определить, к какой части приложения она относится.

### Только внешний вид

Изменять:

```text
MainWindow.h
MainWindow.cpp
```

### Новая команда управления

Обычно изменяются:

```text
MainWindow.cpp
RobotConnection.*
```

Если команда новая для всей системы, дополнительно потребуется изменить код Raspberry Pi и Arduino вне этой папки.

### Новые данные от робота

Изменять:

```text
Telemetry.h
MainWindow.cpp
```

При изменении формата сообщения потребуется также изменить источник телеметрии вне этой папки.

### Новый видеорежим или новый формат кадров

Изменять:

```text
VideoConnection.*
```

Если меняется протокол, источник видеопотока вне этой папки также должен использовать тот же формат.

### Новый класс

1. Создать `.h` и `.cpp`.
2. Добавить их в `CMakeLists.txt`.
3. Подключить класс в нужном месте приложения.
4. Пересобрать проект.

# Основная схема классов

```text
main.cpp
    |
    v
MainWindow
    |
    +--------------------+
    |                    |
    v                    v
RobotConnection     VideoConnection
    |                    |
    v                    v
Telemetry            QImage/JPEG
```

`MainWindow` отвечает за интерфейс и связывает остальные классы.

`RobotConnection` отвечает за TCP-обмен командами и телеметрией.

`VideoConnection` отвечает только за получение и декодирование видеокадров.

`Telemetry` отвечает за представление и разбор телеметрии.

---

# Что не следует смешивать

При расширении проекта желательно сохранять разделение ответственности:

- внешний вид и пользовательские действия — `MainWindow`;
- TCP робота — `RobotConnection`;
- TCP видео — `VideoConnection`;
- формат телеметрии — `Telemetry`;
- сборка — `CMakeLists.txt`.

Например, не следует помещать разбор TCP видеокадров непосредственно в `MainWindow.cpp`, если для этого уже существует `VideoConnection`.

---

# Важное ограничение текущей версии

Адрес Raspberry Pi прописан непосредственно в `MainWindow.cpp`.

Если приложение будет использоваться на нескольких роботах или в разных сетях, следующим шагом имеет смысл вынести IP и порты в отдельную конфигурацию.

Журнал оператора и CSV телеметрии сохраняются между запусками. Видеособытия записи также попадают в постоянный журнал с локальной временной отметкой ПК.
