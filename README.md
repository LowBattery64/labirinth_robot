# OmegaBot — телеуправление и видеосвязь

Программная часть колесного робота OmegaBot: прошивка Arduino, сервер Raspberry Pi и операторское приложение для Windows.

## Архитектура

- **Arduino ARP-DEK-STR-02** — управление двумя приводными колёсами, датчики безопасности, энкодеры, телеметрия и выполнение заранее переданного пакета команд.
- **Raspberry Pi 3B** — TCP-сервер управления, связь с Arduino через USB Serial и видеосервер USB-камеры.
- **ПК оператора** — Qt 6 приложение для телеуправления, просмотра видео, контроля телеметрии и записи журнала.

## Сеть и подключения

| Назначение | Параметр |
|---|---|
| Raspberry Pi | `10.25.39.101` |
| Arduino Serial | `/dev/ttyUSB0`, 115200 бод |
| Управление и телеметрия | TCP `5000` |
| Видеопоток | TCP `5001` |
| Управление качеством и записью видео | TCP `5002` |
| USB-камера Raspberry Pi | обычно `/dev/video0` |

Адрес ПК оператора зависит от сети. Если адрес Raspberry Pi изменится, обновите его в настройках подключения операторского приложения.

## Структура проекта

| Файл или каталог | Назначение |
|---|---|
| `str02-controller.ino` | Прошивка Arduino: моторы, ИК- и ультразвуковые датчики, энкодеры, команды, пользовательские пакеты и телеметрия |
| `labirinth_server.cpp` | TCP-сервер Raspberry Pi: связь с оператором и Arduino, временные отметки, журнал событий и телеметрия |
| `usb_camera_server.cpp` | Видеосервер USB-камеры на базе OpenCV/V4L2, передача кадров и управление записью |
| `operator_ui/` | Qt 6 приложение оператора |
| `operator_ui/OperatorLogger.*` | Локальное журналирование событий и телеметрии на ПК |
| `scripts/start_usb_camera_robot.sh` | Сборка и запуск сервера управления и видеосервера |
| `scripts/stop_usb_camera_robot.sh` | Остановка серверов, запущенных стартовым скриптом |

## Запуск

### 1. Подготовить Arduino

1. Подключите ARP-DEK-STR-02 к ПК.
2. Откройте `str02-controller.ino` в Arduino IDE.
3. Выберите плату **Arduino Mega** и загрузите прошивку.
4. Подключите плату к Raspberry Pi.
5. Убедитесь, что устройство определяется как `/dev/ttyUSB0`. Если используется другой путь, задайте переменную `SERIAL_DEVICE` при запуске скрипта.

### 2. Запустить серверы на Raspberry Pi

Подключитесь к Raspberry Pi:

```bash
ssh raspberry@10.25.39.101
cd ~/labirinth_robot
git pull
```

Установите зависимости для видеосервера:

```bash
sudo apt update
sudo apt install -y libopencv-dev pkg-config
```

Проверьте подключение платы и камеры:

```bash
ls /dev/ttyUSB*
ls /dev/video*
```

Запустите сервер управления и видеосервер:

```bash
chmod +x scripts/start_usb_camera_robot.sh scripts/stop_usb_camera_robot.sh
./scripts/start_usb_camera_robot.sh
```

Скрипт проверяет наличие Serial-устройства и USB-камеры, компилирует и запускает оба сервера. По умолчанию используется `/dev/ttyUSB0`, камера `/dev/video0` и каталог видеозаписей:

```text
/media/raspberry/76E8-CACF/omegabot_recordings
```

Остановить серверы:

```bash
./scripts/stop_usb_camera_robot.sh
```

Проверить процессы и порты:

```bash
ps aux | grep -E 'labirinth_server|usb_camera_server'
ss -lntp | grep -E ':5000|:5001|:5002'
```

Журналы запуска серверов находятся в корне репозитория: `server_console.log` и `usb_camera_console.log`.

### 3. Собрать операторское приложение на Windows

Для сборки необходимы Qt 6 (модули Widgets и Network), CMake и совместимый C++17-компилятор.

Из корня репозитория выполните:

```powershell
cmake -S operator_ui -B operator_ui/build -G "Visual Studio 17 2022" -A x64
cmake --build operator_ui/build --config Release
```

Запустите приложение:

```powershell
operator_ui/build/Release/OmegaBotOperator.exe
```

Приложение подключается к Raspberry Pi по адресу `10.25.39.101): управление и телеметрия — порт `5000`, видео — `5001`, управление видео — `5002`.

## Управление роботом

| Клавиша | Действие |
|---|---|
| `W` / `↑` | Вперёд |
| `S` / `↓` | Назад |
| `A` / `←` | Влево |
| `D` / `→` | Вправо |
| `Space` | Стоп |

Команда движения сохраняется после нажатия; отпускание клавиши само по себе не останавливает робот. Для остановки отправьте команду стоп. В прошивке действует watchdog: если команды обычного телеуправления перестают поступать, моторы останавливаются.

Перед запуском робота убедитесь, что вокруг достаточно свободного пространства. Аварийная остановка в приложении отправляет команду остановки по сети и не заменяет аппаратное отключение питания.

## Пользовательские пакеты команд

Оператор может задать последовательность команд в редакторе пакета. Каждая строка содержит команду и длительность в миллисекундах:

```text
F 700
R 1900
B 700
```

Поддерживаются команды:

- `F` — вперёд;
- `B` — назад;
- `L` — поворот влево;
- `R` — поворот вправо;
- `S` — остановка на указанное время.

Приложение передаёт пакет в формате:

```text
P,F:700;R:1900;B:700
```

Arduino принимает пакет целиком, сохраняет шаги в оперативной памяти и выполняет их независимо от TCP-соединения. Пакет может содержать не более 24 шагов. Его необходимо отправить до въезда в зону без связи. Ручная команда движения, полученная во время выполнения, отменяет пакет.

**Важно:** пакет задаёт весь требуемый маршрут сам по себе. Прошивка не подставляет в него автоматически разворот или обратный путь. Потеря связи во время обычного телеуправления приводит к остановке по watchdog; не следует считать это автоматическим возвращением в зону связи.

## Датчики и телеметрия

Прошивка использует передний ИК-датчик, три ультразвуковых дальномера и два энкодера. Передняя ультразвуковая защита блокирует движение вперёд при обнаружении препятствия; режим тарана отключает эту защиту и должен использоваться осознанно.

Телеметрия передаётся через Raspberry Pi в операторское приложение. В строке телеметрии используются поля:

- `IR` — состояние переднего ИК-датчика;
- `US` — расстояния центрального, левого и правого ультразвуковых датчиков;
- `ENC` — показания левого и правого энкодеров;
- `SAFE` — состояние передней защиты;
- `CMD` — последняя команда;
- `WD` — состояние watchdog;
- временная отметка — время формирования записи на Raspberry Pi.

## Логи и видеозаписи

На Raspberry Pi сервер создаёт в каталоге репозитория:

- `robot.log` — события и команды с временными отметками;
- `telemetry.csv` — полученные строки телеметрии;
- `server_console.log` — вывод сервера управления;
- `usb_camera_console.log` — вывод видеосервера.

Операторское приложение сохраняет журналы в каталоге данных приложения Qt, обычно внутри `%LOCALAPPDATA%/OmegaBotOperator/logs/`:

- `operator.log` — локальные и серверные события;
- `telemetry.csv` — принятые образцы телеметрии.

USB-камера не начинает запись автоматически при запуске сервера. Запись запускается из операторского приложения. Видео сохраняется сегментами AVI с кодеком MJPG; стандартная длительность сегмента — 600 секунд. Каталог записей по умолчанию:

```text
/media/raspberry/76E8-CACF/omegabot_recordings
```

Проверить созданные файлы можно командой:

```bash
ls -lh /media/raspberry/76E8-CACF/omegabot_recordings
```

## Известные ограничения

- Возврат по маршруту не вычисляется автоматически из пользовательского пакета: нужные повороты и обратные участки необходимо задать оператору.
- Команды пакета основаны на длительности, а не на точном измерении пройденного расстояния. Реальная траектория зависит от поверхности, нагрузки, питания и механики робота.
- При потере связи во время обычного телеуправления watchdog останавливает моторы. Автономное продолжение предусмотрено только для пакета, уже полученного Arduino целиком.
- Адреса, имена устройств и путь к USB-накопителю могут отличаться в другой конфигурации; при необходимости задавайте соответствующие параметры запуска.
