# Робот — телеуправление и видеосвязь

Документация текущей версии проекта: запуск, архитектура, датчики, видео, логи и дальнейшие задачи.

## Сеть

| Устройство | Адрес |
|---|---|
| Raspberry Pi 3B | 10.25.39.101 |
| ПК оператора | Адрес зависит от сети |

- TCP 5000 — управление, телеметрия и события сервера.
- TCP 5001 — видеопоток с USB-камеры.
- TCP 5002 — управление качеством и записью видео.

TrackingCam3 в текущей версии больше не используется.

## Компоненты

`str02-controller.ino` — прошивка ARP-DEK-STR-02. Управляет двумя моторами, принимает команды движения и пользовательские пакеты, ведёт историю перемещений, считывает передний IR, три ультразвуковых датчика и два энкодера, отправляет телеметрию. Watchdog останавливает обычное телеуправление при отсутствии команд. Полученный пакет выполняется локально на Arduino и продолжает выполняться после потери TCP-связи.

`labirinth_server.cpp` — Raspberry Pi сервер. TCP 5000, USB Serial `/dev/ttyUSB0`, 115200 бод. Передает команды Arduino, принимает телеметрию, добавляет временные отметки, передает оператору телеметрию и события сервера, а также пишет серверные логи и телеметрию.

`usb_camera_server.cpp` — сервер новой USB-камеры на Raspberry Pi. Открывает камеру через V4L2/OpenCV, формирует JPEG-кадры и передает их по TCP 5001. Отдельный TCP 5002 используется для выбора качества видео и запуска/остановки записи.

`camera_bridge.py` — старый видеомост TrackingCam3. Он сохранён в репозитории для прежней конфигурации, но в текущей схеме запуска USB-камеры не используется.

`operator_ui/` — Qt 6 приложение оператора. Управление роботом, видеопоток, телеметрия, состояние соединения, журнал событий, управление качеством видео и записью.

`operator_ui/OperatorLogger.*` — постоянное журналирование на ПК оператора. Сохраняет локальные и серверные события, а также телеметрию в CSV между запусками приложения.

`scripts/start_usb_camera_robot.sh` — сборка и запуск `labirinth_server` и `usb_camera_server` в текущей USB-конфигурации.

`scripts/stop_usb_camera_robot.sh` — остановка `usb_camera_server` и `labirinth_server`, запущенных предыдущим скриптом.

## Полный порядок запуска

### 1. Arduino

1. Подключить ARP-DEK-STR-02 к ПК по USB.
2. Открыть `str02-controller.ino` в Arduino IDE.
3. Выбрать `Arduino Mega`.
4. Загрузить прошивку.
5. Отключить USB от ПК.
6. Подключить плату к Raspberry Pi.
7. Убедиться, что Raspberry Pi видит плату как `/dev/ttyUSB0`.

### 2. Raspberry Pi

Подключиться к Raspberry Pi:

    ssh raspberry@10.25.39.101

Перейти в репозиторий:

    cd ~/labirinth_robot
    git pull

Проверить Serial:

    ls /dev/ttyUSB*

Ожидается:

    /dev/ttyUSB0

Проверить USB-камеру:

    ls /dev/video*

В текущей конфигурации ожидается:

    /dev/video0

Для запуска текущей конфигурации с USB-камерой сначала установить OpenCV для C++:

    sudo apt update
    sudo apt install -y libopencv-dev pkg-config

Затем сделать скрипты исполняемыми:

    chmod +x scripts/start_usb_camera_robot.sh
    chmod +x scripts/stop_usb_camera_robot.sh

Запустить сервер робота и USB-камеру:

    ./scripts/start_usb_camera_robot.sh

Скрипт:
- проверяет репозиторий;
- проверяет `/dev/ttyUSB0`;
- проверяет USB-камеру;
- компилирует и запускает `labirinth_server`;
- компилирует `usb_camera_server.cpp` через `pkg-config opencv4`;
- запускает видеосервер.

Порты текущей конфигурации:

    TCP 5000 — управление и телеметрия
    TCP 5001 — видео
    TCP 5002 — управление видео

Проверить запущенные процессы и порты:

    ps aux | grep -E 'labirinth_server|usb_camera_server'
    ss -lntp | grep -E ':5000|:5001|:5002'

При необходимости проверить журнал запуска:

    cat server_console.log
    cat usb_camera_console.log

Остановить оба сервера:

    ./scripts/stop_usb_camera_robot.sh

### 3. Запись видео

USB-камера не начинает запись автоматически только от факта запуска сервера.

Каталог записей:

    /media/raspberry/76E8-CACF/omegabot_recordings

Создать каталог при необходимости:

    mkdir -p /media/raspberry/76E8-CACF/omegabot_recordings

Запись запускается кнопкой оператора через TCP 5002.

USB-сервер создаёт сегменты AVI с кодеком MJPG. Стандартная длительность сегмента — 600 секунд.

Проверить записи:

    ls -lh /media/raspberry/76E8-CACF/omegabot_recordings

### 4. Операторское приложение

На Windows из корня репозитория:

    cmake -S operator_ui -B operator_ui/build -G "Visual Studio 17 2022" -A x64

Затем:

    cmake --build operator_ui/build --config Release

Запустить:

    operator_ui/build/Release/OmegaBotOperator.exe

Приложение в текущей ветке подключается к Raspberry Pi:

    10.25.39.101:5000

    10.25.39.101:5001

Управление качеством и записью выполняются через:

    10.25.39.101:5002

Для сборки требуется Qt 6 с компонентами Widgets и Network, а также CMake и совместимый C++17-компилятор.

## Управление

| Клавиша | Действие |
|---|---|
| W / ↑ | вперед |
| S / ↓ | назад |
| A / ← | влево |
| D / → | вправо |
| Space | стоп |

Команда сохраняется после нажатия. Отпускание клавиши не останавливает робота.

В интерфейсе также предусмотрены кнопки остановки, аварийной остановки, выбора качества видео, управления записью и редактор пользовательского пакета.

### Пользовательский пакет и резервный возврат

Оператор сам задаёт последовательность команд и длительность каждого шага. Например:

    F 700
    R 1900
    B 700

Интерфейс преобразует её в пакет:

    P,F:700;R:1900;B:700

Пакет отправляется на Raspberry Pi и целиком передаётся Arduino. После успешного получения Arduino сохраняет пакет в памяти и выполняет его самостоятельно. Поэтому пакет продолжает выполняться после потери TCP-связи.

Сам Arduino не содержит заранее заданной последовательности «проехать 10 см → повернуть 180° → вернуться». Если оператору нужен такой маршрут, он задаёт именно его в редакторе. Если нужен другой маршрут, оператор меняет пакет.

Одновременно Arduino ведёт историю выполненных перемещений. Для каждого участка сохраняются команда и длительность. История используется как резервный механизм возврата: если после выполнения текущего пакета связь всё ещё потеряна, робот может пройти сохранённый путь в обратном порядке, инвертируя команды (F↔B, L↔R).

История также ведётся при обычном телеуправлении. При обычной потере связи сначала срабатывает watchdog и останавливает робот, а если связь не восстанавливается, резервный возврат по истории запускается через несколько секунд.

Таким образом, пользовательский пакет остаётся основным способом заранее задать маршрут в зоне без связи, а MoveHistory обеспечивает дополнительный вариант возврата без заранее заданной в прошивке траектории. Возврат по истории является приближённым: он основан на времени движения, а не на полноценной локализации робота.

## Датчики и телеметрия

Телеметрия передаётся от Arduino через `labirinth_server` на ПК оператора.

Пример строки:

    T,2026-09-27 21:06:25.123,IR,0,US,120,85,90,ENC,123,119,SAFE,0,CMD,F,WD,0

Используемые поля:

- `IR` — состояние переднего ИК-датчика;
- `US` — расстояния центрального, левого и правого ультразвуковых датчиков;
- `ENC` — импульсы левого и правого энкодеров;
- `SAFE` — состояние передней защиты;
- `CMD` — последняя команда;
- `WD` — состояние watchdog;
- временная отметка — время формирования телеметрии на Raspberry Pi.

## Логи и записи

### Raspberry Pi

При запуске `labirinth_server` создаются серверные файлы в каталоге репозитория:

    ~/labirinth_robot/robot.log
    ~/labirinth_robot/telemetry.csv

Кроме них скрипт запуска использует:

    ~/labirinth_robot/server_console.log
    ~/labirinth_robot/usb_camera_console.log

`robot.log` содержит события сервера и команды с временными отметками.

`telemetry.csv` содержит телеметрию.

`usb_camera_console.log` содержит вывод USB-видеосервера, в том числе сообщения об открытии камеры и записи видео.

### ПК оператора

`operator_ui` постоянно дописывает два файла:

    %LOCALAPPDATA%/OmegaBotOperator/logs/operator.log
    %LOCALAPPDATA%/OmegaBotOperator/logs/telemetry.csv

Фактический путь формируется через `QStandardPaths::AppLocalDataLocation`, поэтому он не зависит от каталога, из которого запущен `.exe`. Файлы не очищаются при запуске приложения.

`operator.log` содержит локальное время ПК, серверное время при наличии, источник события и текст события.

`telemetry.csv` содержит отдельную строку на каждый принятый образец телеметрии: локальное время ПК, время телеметрии на Raspberry Pi, IR, три значения US, SAFE, CMD, WD и исходную строку телеметрии.

При повторном запуске `operator_ui` последние записи постоянного журнала снова отображаются в панели журнала.

## Взаимодействие

Управление:

    ПК → TCP 5000 → labirinth_server → USB Serial → str02-controller.ino → моторы.

Телеметрия:

    str02-controller.ino → USB Serial → labirinth_server → TCP 5000 → ПК.

Видео:

    USB-камера → OpenCV/V4L2 → usb_camera_server → TCP 5001 → ПК.

Управление видео:

    ПК → TCP 5002 → usb_camera_server.

Запись:

    USB-камера → usb_camera_server → /media/raspberry/76E8-CACF/omegabot_recordings

- базовое телеуправление;
- передача телеметрии;
- серверное логирование;
- постоянное логирование на ПК оператора;
- передача видео с новой USB-камеры;

- отдельная команда автоматической инспекции/возврата.

## Ограничения

- Raspberry Pi: `10.25.39.101`.
- Serial: `/dev/ttyUSB0`, 115200.
- USB-камера: `/dev/video0` в текущей конфигурации.
- Управление/телеметрия: TCP 5000.
- Видео: TCP 5001.
- Управление видео: TCP 5002.
- OpenCV C++: `libopencv-dev` и `pkg-config`.
- Запись: `/media/raspberry/76E8-CACF/omegabot_recordings`.
- Watchdog обычного телеуправления и логика выполнения пользовательского пакета определяются прошивкой Arduino.
- После отключения ПК `labirinth_server` продолжает работать, сохраняет телеметрию и ждёт нового подключения оператора.
- TrackingCam3 не является частью текущей схемы USB-видеокамеры.
